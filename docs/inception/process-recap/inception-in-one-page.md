# How inception worked, in one page

For Ale. The full detail is in the [AI recap](recap.md); ideas for reusable skills are in the [proposals](skill-proposals.md).

## The idea

We built the case for Band Studio OS before writing any product code. One document at a time, one pull request each, every decision written in the [decision log](../decision-log.md).

## The ten steps, in order

1. **Set up the rules.** A workflow, eleven exit criteria and a status tracker.
2. **Write the foundation.** The problem, the user (the band's "driver"), the value and the first decisions.
3. **Make research honest.** A framework with a skeptic agent that re-checks sources itself (from saved copies when a site blocks it).
4. **Test whether bands like this exist.** Reality checks gave "needs interviews". Provisional personas and a research plan followed.
5. **Fix the limits.** Constraints (part-time team, under 100 EUR a month) and the main success number: approved campaigns per month.
6. **Study the competition and the market.** The result was "Reshape": a brand hub for coherent creative, not an AI poster generator. Bandsintown Boost counts as a reach competitor. Canva could not be opened, so Gemini Deep Research ran as a second route.
7. **Define the first version.** Setup and pre-gig only, with a free pilot.
8. **Show it.** Prototype v1 felt generic. We designed three alternatives, you chose the Gig Wall, and v2 and v2.1 followed.
9. **Gather the story.** The Product Brief Pack: one honest source for decks and pitches, with a red, amber, green gap record.
10. **Hand over.** The architecture handoff, reviewed by an independent agent that found 3 critical and 8 important problems, all dealt with.

## What is still open

- Real bands: no interviews, blind test or price test yet.
- Prototype v2.2 is in progress elsewhere, and the exit gate has not been run.

## Five lessons

- When a source is blocked, add a second route instead of stopping.
- A skeptic that checks sources itself changes verdicts. Keep it.
- A rejected prototype leads to design alternatives, not another guess.
- Parallel work needs reserved decision numbers.
- Always say what was not checked.
